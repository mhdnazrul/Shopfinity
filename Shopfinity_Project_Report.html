1. Introduction

1.1 Introduction

The global e-commerce industry has experienced exponential growth over the past decade, driven by increasing internet penetration, the proliferation of mobile devices, and evolving consumer expectations for convenience and speed. According to industry reports, worldwide e-commerce sales are projected to surpass USD 8 trillion by 2027, underscoring the critical importance of robust, scalable, and user-centric online retail platforms. Modern consumers expect sub-second page loads, intuitive navigation, secure payment workflows, and real-time visibility into their order status. Meeting these expectations demands a technology stack that balances developer productivity with runtime performance and security.

Shopfinity is a production-grade, full-stack e-commerce platform conceived to address these demands. It combines a Next.js 16 (App Router) storefront with an ASP.NET Core 9 REST API and a PostgreSQL 16 relational database, delivering a comprehensive suite of features including product discovery, cart and wishlist management, secure authentication, order placement, reviews, and administrative control. The system is deployed on Render with an automated CI/CD pipeline, ensuring continuous delivery of quality software.

1.2 Motivation

The primary motivation behind Shopfinity was to modernise the online shopping experience by building a platform that demonstrates industry best practices in full-stack web development. Many existing open-source e-commerce solutions rely on monolithic architectures that are difficult to scale and maintain, or employ outdated technology stacks that hinder developer productivity. Shopfinity was built to bridge this gap by:

  • Adopting Clean Architecture on the backend to enforce clear separation of concerns and improve long-term maintainability.
  • Leveraging Next.js App Router with server and client components to deliver fast, SEO-friendly pages with rich interactivity.
  • Implementing security-first design with JWT tokens in HttpOnly cookies, CSRF double-submit protection, rate limiting, and input validation.
  • Providing a hands-on case study for learning production-grade engineering practices across the frontend, backend, and database layers.

1.3 Application

Shopfinity is designed primarily for Business-to-Consumer (B2C) retail scenarios. Its architecture and feature set make it suitable for the following applications:

  • Small-to-Medium Online Retailers: Businesses seeking a modern, customisable storefront with integrated product management, cart functionality, and order tracking.
  • Multi-Category Product Catalogs: Retailers offering diverse product categories (electronics, apparel, home goods) benefit from the category-based organisation, search with trigram suggestions, and tag-based filtering.
  • Educational and Portfolio Projects: Software engineering students and professionals can use Shopfinity as a reference implementation of Clean Architecture, JWT security, and full-stack TypeScript/C# development.
  • Startup MVPs: Entrepreneurs can fork the repository as a foundation for a minimum viable product, extending it with payment integration and additional business logic.

1.4 Objectives

The development of Shopfinity was guided by the following measurable objectives:

  1. Scalability: Design a layered backend architecture (Domain, Application, Infrastructure, API) that supports horizontal scaling and independent service evolution.
  2. User-Friendly Interface: Deliver a responsive, aesthetically polished storefront with sub-second navigation, typeahead search powered by PostgreSQL pg_trgm, and a streamlined checkout flow.
  3. Security: Implement defence-in-depth security including JWT authentication with HttpOnly cookie storage, CSRF token validation, rate limiting on sensitive endpoints, and parameterised database queries via Entity Framework Core.
  4. Comprehensive Feature Set: Provide end-to-end e-commerce capabilities — product catalogue, search, cart, wishlist, checkout with stock validation, order status tracking, product reviews, and an administrative dashboard.
  5. Automated Deployment: Establish a CI/CD pipeline on Render with automated builds, health checks, and zero-downtime deployments triggered by Git push events.
  6. Testability: Achieve meaningful test coverage through white-box unit tests (xUnit with in-memory SQLite) and black-box API/UI testing strategies.

3. Methodology

3.1 Use Case Diagram Description

The Shopfinity system identifies two primary actors: Customer and Administrator, both interacting with the central Shopfinity System.

Customer Use Cases:

  • Register / Login: The customer creates an account or authenticates. Login extends to "Receive JWT Tokens" and "Initialize CSRF Token."
  • Browse Products: Includes "Search Products" (with typeahead suggestions) and "Filter by Category/Price."
  • Manage Cart: Includes "Add to Cart," "Update Quantity," and "Remove Item."
  • Manage Wishlist: Includes "Add to Wishlist" and "Remove from Wishlist."
  • Checkout: Extends "Validate Stock," "Create Order," and "Clear Cart." Includes the optional "Provide Idempotency Key."
  • View Orders: The customer views order history and real-time status.
  • Submit Review: The customer rates and reviews a purchased product.

Administrator Use Cases:

  • Manage Products: Full CRUD operations including image upload.
  • Manage Categories: Create, edit, delete, and reorder categories.
  • Manage Orders: View all orders and update order status.
  • View Dashboard: Access summary metrics.

3.2 Activity Diagram Description

The primary activity flow for the Checkout Process is described as follows:

  1. Start: Customer clicks "Proceed to Checkout" on the Cart page.
  2. Decision — Authenticated? If No → redirect to Login page → return to Cart after login. If Yes → continue.
  3. System: Retrieve Cart Items — The API fetches the user's cart with product details.
  4. Decision — Cart Empty? If Yes → display "Your cart is empty" message → End. If No → continue.
  5. System: Validate Stock — For each CartItem, verify Product.StockQuantity ≥ CartItem.Quantity.
  6. Decision — Stock Sufficient? If No → return error "Insufficient stock for [Product Name]" → End. If Yes → continue.
  7. System: Check Idempotency Key — If X-Idempotency-Key header is present and matches an existing order, return the existing order → End.
  8. System: Create Order — Within a database transaction: create Order record, create OrderItem records with UnitPrice snapshot, decrement Product.StockQuantity, clear CartItems.
  9. System: Commit Transaction — Persist all changes atomically.
  10. Response: Return 201 Created with OrderResponseDto.
  11. End.

3.3 Sequence Diagram Description

The sequence diagram for the User Login Flow involves four participants: Browser (Next.js), API Gateway (ASP.NET Core), AuthService, and PostgreSQL Database.

  1. Browser → API: POST /api/v1/auth/login with { email, password } body.
  2. API → AuthService: Call LoginAsync(dto, cancellationToken).
  3. AuthService → Database: Query AspNetUsers by email using UserManager.FindByEmailAsync().
  4. Database → AuthService: Return ApplicationUser record (or null).
  5. AuthService: Decision — If user is null or password invalid → throw UnauthorizedAccessException.
  6. AuthService → JwtTokenGenerator: Call GenerateAccessToken(user, roles) → returns signed JWT string.
  7. AuthService → Database: INSERT into RefreshTokens table with token value, user ID, and expiry.
  8. AuthService → API: Return AuthResponseDto { AccessToken, RefreshToken, Email, Roles }.
  9. API → Browser: Set-Cookie: shopfinity_token=JWT (HttpOnly, Secure, SameSite=Lax). Set-Cookie: shopfinity_refresh=RefreshToken. Set-Cookie: XSRF-TOKEN=CsrfValue (non-HttpOnly, for JS access). Return 200 OK with response body.
  10. Browser: Store authentication state in React Context. Redirect to home page.

3.4 Class Diagram Description

The domain model consists of the following entity classes, all inheriting from the abstract BaseEntity class which provides Id (Guid), CreatedAt, and UpdatedAt audit fields:

  • Product — Properties: Name, Slug, Description, Price (decimal), StockQuantity (int), ImageUrl, Tags (List<string>), SearchVector (NpgsqlTsVector), RowVersion (byte[]). Relationships: belongs to one Category (via CategoryId FK); has many OrderItems, CartItems, WishlistItems, and ProductReviews.
  • Category — Properties: Name, Slug, Description, ImageUrl, DisplayOrder (int). Relationships: has many Products.
  • Cart — Properties: UserId (string). Relationships: has many CartItems.
  • CartItem — Properties: CartId (Guid), ProductId (Guid), Quantity (int). Relationships: belongs to one Cart, references one Product.
  • Order — Properties: UserId, TotalAmount (decimal), Status (OrderStatus enum), IdempotencyKey. Relationships: has many OrderItems.
  • OrderItem — Properties: OrderId (Guid), ProductId (Guid), Quantity (int), UnitPrice (decimal). Relationships: belongs to one Order, references one Product.
  • WishlistItem — Properties: UserId, ProductId. Relationships: references one Product.
  • ProductReview — Properties: UserId, UserName (denormalised), ProductId, Rating (int 1–5), Title, Comment. Relationships: references one Product.
  • RefreshToken — Properties: UserId, Token, ExpiresAt (DateTime). Relationships: belongs to one ApplicationUser.

3.5.2 Frontend Architecture

The Next.js 16 frontend uses the App Router paradigm with a clear separation of concerns:

  • /app — Route definitions and page components (home, products, cart, checkout, orders, wishlist, login, register, admin).
  • /components — Reusable UI components (Button, FormError, product cards, navigation).
  • /services — Axios-based API service functions for each domain (authService, productService, cartService, etc.).
  • /hooks — Custom React hooks wrapping TanStack Query (React Query) for data fetching and mutations.
  • /context — React Context providers for authentication state management.
  • /types — TypeScript type definitions matching backend DTOs.
  • /providers — Application-level providers (QueryClientProvider, AuthProvider).

4. System Implementation Overview

4.1 Features

4.1.1 User Authentication and Security

Authentication is built on ASP.NET Core Identity extended with a custom JwtTokenGenerator service. On successful login, the API issues two tokens: a short-lived JWT access token (stored in the shopfinity_token HttpOnly cookie) and a long-lived refresh token (stored in shopfinity_refresh HttpOnly cookie and persisted in the RefreshTokens database table). CSRF protection is enforced via the CsrfValidationMiddleware, which validates the X-XSRF-TOKEN request header against the XSRF-TOKEN cookie for all mutating HTTP methods. Password policy enforces minimum 8 characters with uppercase, lowercase, digit, and non-alphanumeric requirements. The auth endpoint group is protected by a rate limiter (AuthRatePolicy) allowing a maximum of 5 requests per minute per IP address.

4.1.2 Product Catalog and Search

The product catalog is exposed through the ProductsController (9 API controllers total), supporting paginated listing with filtering by search term, price range, and category. The SearchProductsAsync service method queries PostgreSQL using EF Core with LINQ-based filters. For typeahead suggestions, the SearchSuggestionsAsync method leverages PostgreSQL's pg_trgm GIN index for fast trigram similarity matching, returning up to 10 ranked suggestions. Product detail pages are served by slug-based lookup, with results cached in IMemoryCache to reduce repeated database queries.

4.1.3 Cart and Wishlist Management

The shopping cart is server-backed, with each authenticated user owning exactly one Cart record. CartItems are added, updated in quantity, or removed through the CartsController. Wishlist items are independently managed through the WishlistsController, supporting add, remove, and list operations with conflict handling to prevent duplicate entries. Both features require user authentication via the [Authorize] attribute.

4.1.4 Checkout and Order Management

Order placement is handled by the CheckoutCartAsync service method. The process includes: stock availability validation, total amount calculation, atomic order record creation with associated OrderItems (capturing UnitPrice at time of order), stock quantity decrement, and cart clearance — all within a single database transaction. An idempotency key (X-Idempotency-Key header) prevents duplicate orders from retry requests. Order status transitions through the OrderStatus enum: Pending → Processing → Shipped → Delivered (or Cancelled), managed by administrators via PUT /api/v1/orders/{id}/status.

4.1.5 Product Reviews

Authenticated users can submit product reviews consisting of a 1–5 star rating, title, and comment. The UserName field is denormalised onto the ProductReview entity for rapid display without requiring a join to the Identity tables. Submissions are rate-limited via the ReviewSubmissionPolicy (3 reviews per 5 minutes) to prevent abuse.

4.1.6 Administrative Dashboard

The admin panel is accessible to users with the Admin role and provides: full CRUD management of products and categories, image upload via the UploadsController (stored in wwwroot/uploads), a dashboard summary view via the DashboardController, and order status management. Role-based access control is enforced using [Authorize(Roles = AppRoles.Admin)] attributes.

4.2 Key User Interfaces

4.2.1 Home Page

The home page (/app/page.tsx, 6.7 KB) serves as the primary landing experience. It features a hero section with promotional banners, a curated grid of featured product categories, and a selection of trending products. The page leverages Next.js server components for initial data fetching, ensuring fast first contentful paint. Navigation includes a persistent header with the Shopfinity logo, a search bar with real-time typeahead suggestions, and quick-access icons for cart, wishlist, and user account.

4.2.2 Product Detail Page

The product detail page (/app/products/[slug]) displays comprehensive product information including high-resolution product images, the product name, price, stock availability indicator, full description, and tags. Below the product details, a reviews section displays existing customer reviews with star ratings and a form for authenticated users to submit new reviews. An "Add to Cart" button triggers a React Query mutation that calls the Cart API and updates the cart count in the navigation bar. A "Add to Wishlist" toggle button allows users to save products for later.

4.2.3 Checkout Flow

The checkout flow begins on the Cart page (/app/cart), which displays all cart items with quantity adjusters and a running total. Clicking "Proceed to Checkout" navigates to /app/checkout, which presents an order summary with itemised pricing. Upon confirmation, the frontend sends a POST request to /api/v1/orders/checkout with an auto-generated idempotency key. On success, the user is redirected to an order confirmation view showing the new order ID, status ("Pending"), and order details. The Orders page (/app/orders) provides a chronological list of all past orders with their current status.

5. Risk Analysis

5.1 Assessing the Risk

The following technical risks were identified during the development and deployment of Shopfinity:

  • Server Downtime: Render's managed hosting mitigates most infrastructure risks, but application-level crashes (unhandled exceptions, memory leaks) can cause service interruptions. The ExceptionMiddleware catches all unhandled exceptions and returns structured error responses, preventing process crashes.
  • Database Lock Contention: Concurrent checkout operations on popular products may cause database row-level lock contention on the Products table during stock decrement. EF Core's optimistic concurrency control via the RowVersion column detects conflicts and throws DbUpdateConcurrencyException, which the application handles gracefully.
  • Authentication Token Compromise: If a JWT access token is intercepted, an attacker gains temporary access to the victim's account. The short token lifetime (configurable, typically 15 minutes) and HttpOnly cookie storage significantly reduce this attack surface.
  • API Abuse and DDoS: Public-facing search and product listing endpoints are vulnerable to excessive automated requests. The layered rate limiting strategy (global 100/min + endpoint-specific policies) provides defence against both targeted and distributed abuse.
  • Data Loss from Failed Transactions: Partial checkout failures (e.g., stock decrement succeeds but order creation fails) could lead to data inconsistency. The use of EF Core's implicit transaction scope ensures atomicity — either all operations succeed or all are rolled back.

6. Social and Security Impact

6.1 Social Impact

Shopfinity demonstrates how modern web technologies can empower local businesses to establish a professional online presence without the overhead costs of proprietary e-commerce platforms. By providing an open-source, production-ready codebase, Shopfinity enables:

  • Small Business Digitalisation: Local retailers can deploy a fully functional online store, reaching customers beyond their geographical limitations and competing with established e-commerce giants.
  • Employment and Skill Development: The project serves as an educational resource for aspiring software engineers, providing a real-world case study of Clean Architecture, full-stack TypeScript/C# development, and cloud deployment practices.
  • Consumer Convenience: Features such as typeahead search, wishlist management, and real-time order tracking improve the consumer shopping experience, reducing friction and increasing purchase confidence.
  • Accessibility: The responsive frontend design ensures that users on mobile devices — which represent the majority of internet users in developing regions — can access the full feature set without degradation.

6.2 Security and Reliability

Security and reliability are foundational pillars of Shopfinity's architecture:

  • JWT Authentication: Access tokens are signed with HS256 (symmetric key) and stored in HttpOnly, Secure, SameSite=Lax cookies, preventing JavaScript access and mitigating XSS-based token theft. Refresh tokens enable seamless session extension without re-authentication.
  • CSRF Double-Submit Cookie Pattern: The CsrfValidationMiddleware ensures that all state-changing API requests carry a valid X-XSRF-TOKEN header matching the server-issued XSRF-TOKEN cookie, protecting against cross-site request forgery attacks.
  • PostgreSQL Data Integrity: Foreign key constraints, NOT NULL constraints, UNIQUE constraints (e.g., on Product.Slug, Order.IdempotencyKey), and CHECK constraints (e.g., ProductReview.Rating between 1 and 5) enforce data integrity at the database level, providing a safety net independent of application logic.
  • Structured Logging with Serilog: Every request is tagged with a CorrelationId (via CorrelationIdMiddleware), enabling end-to-end request tracing across log entries. Logs are written to both console and rolling daily files.
  • Health Monitoring: The /health endpoint performs an active PostgreSQL connectivity check, enabling Render and external monitoring tools to detect and respond to service degradation automatically.
  • Transient Fault Handling: Database connections are configured with EnableRetryOnFailure (3 retries, 5-second maximum delay), ensuring resilience against momentary network interruptions or database restarts.

7. Conclusion

The Shopfinity project has successfully demonstrated the end-to-end development of a modern, production-grade e-commerce platform. Through the careful selection of technologies — Next.js 16 for the frontend, ASP.NET Core 9 for the backend, and PostgreSQL 16 for data persistence — the project achieves a balance of developer productivity, runtime performance, and security robustness.

Key learnings from this project include:

  • Clean Architecture Effectiveness: Separating the backend into Domain, Application, Infrastructure, and API layers proved invaluable for testability (white-box testing of service logic with in-memory databases) and maintainability (new features added as self-contained feature folders).
  • Security as a First-Class Concern: Implementing JWT + CSRF + Rate Limiting from the outset was more effective than retrofitting security onto a completed application.
  • PostgreSQL-Specific Optimisations: Leveraging pg_trgm for trigram search suggestions and GIN indexes provided a search experience typically associated with dedicated search engines, without additional infrastructure.
  • TypeScript End-to-End: Sharing type definitions between the frontend (TypeScript interfaces) and backend (DTOs) reduced integration bugs and improved developer confidence during API changes.

Future Enhancements:

  1. Payment Gateway Integration: Integration with Stripe or PayPal for real payment processing.
  2. Real-Time Notifications with SignalR: Push live order status updates to the customer's browser via WebSocket connections.
  3. AI-Based Product Recommendations: A recommendation engine using collaborative filtering and purchase history analysis to suggest relevant products and increase average order value.
  4. Elasticsearch Integration: Dedicated search infrastructure for more powerful full-text search, faceted filtering, and relevance ranking at scale.
  5. React Native Mobile App: A mobile application consuming the existing REST API, extending platform reach to iOS and Android.
  6. Redis Distributed Caching: Replacing IMemoryCache with Redis to support cache sharing across horizontally scaled API instances.
  7. Docker Containerisation: Packaging all services into Docker containers with Docker Compose for consistent development and deployment environments.
  8. Enhanced Analytics Dashboard: Sales analytics, revenue charts, and inventory forecasting using a charting library such as Recharts.
